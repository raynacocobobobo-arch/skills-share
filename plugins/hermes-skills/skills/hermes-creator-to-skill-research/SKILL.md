# Hermes Creator To Skill Research

## Purpose

将优秀创作者的真实经验转化为 Hermes 可复用能力。

目标不是生成内容摘要，而是发现：

- 新工作流
- 新方法论
- 新判断标准
- 可以提升实际项目效率的能力

输入：

- YouTube 字幕
- 文章
- GitHub 项目
- 教程

输出：

- 创作者蒸馏分析
- 可复用原则
- Hermes 能力影响判断
- 必要时生成 Skill 修改建议

## Core Rule

不要：

- 生成普通视频摘要
- 罗列工具名称
- 因为一个案例就新增 Skill
- 设计复杂但无法使用的知识体系

重点回答：

1. 创作者解决了什么实际问题？
2. 他采用了什么工作流程？
3. 哪些经验可以迁移到其他项目？
4. Hermes 当前是否已经具备？
5. 如果缺失，最小应该如何补充？

## Source Discovery Rule

素材定位阶段必须先确认真实输入，不允许直接依赖搜索结果。

### Discovery Priority

执行顺序：

```
用户指定路径

↓

research-input.md / index.json 等索引文件

↓

目录列表读取

↓

根据路径读取原始素材

↓

搜索作为辅助
```

### GitHub Search Limitation

GitHub 搜索索引可能存在延迟。

因此：

- 搜索无结果，不代表文件不存在。
- 不能因为搜索失败停止任务。
- 必须继续检查目录和索引。

### Raw Material Rule

确认素材存在后：

必须读取原始字幕、文章或项目文件。

禁止：

- 根据标题判断内容
- 根据摘要生成结论
- 根据 watchlist 推测观点

# Creator Batch Distillation

## 原则

同一个创作者优先批量分析，不以单个视频作为能力来源。

推荐流程：

```
同一创作者多条素材

↓

整体阅读

↓

寻找重复出现的方法

↓

去除工具新闻和单案例

↓

提取稳定工作流

↓

判断 Hermes 缺口
```

## Batch Rule

- 单条视频只能作为证据。
- 至少观察多个素材后，才判断是否形成方法论。
- 重复出现的工作流程优先级高于单次技巧。
- 不因为某个案例新增 Skill。

## Workflow

原始素材

↓

确认素材入口

↓

批量读取同一创作者素材

↓

提取关键原文证据

↓

寻找重复模式

↓

提取创作者工作流

↓

提炼可复用原则

↓

和已有 Hermes 能力比较

↓

生成最小修改建议

## Output Requirements

每次分析必须包含：

# Creator Distillation

## 来源

作者、素材、背景。

## 创作者核心价值

这个创作者真正贡献的能力是什么。

## 高频重复方法

只记录多个素材中反复出现的方法。

## 创作者工作流

拆解真实执行流程。

## 新发现的方法

只保留可迁移经验。

## 与已有 Hermes 能力比较

判断：

- 已覆盖
- 部分缺失
- 完全缺失

## Skill 影响

如果需要修改：

- 修改哪个文件
- 为什么修改
- 最小修改内容

## Practical Value

判断该经验是否值得进入 Hermes。

低价值内容：

- 单个工具新闻
- 临时模型效果
- 无法复用的技巧

高价值内容：

- 工作流程
- 判断方法
- 可持续复用原则

## Evidence Rule

所有重要结论必须能够追溯到原始素材。

禁止根据标题、摘要或二手描述生成结论。

## Boundary

这个 Skill 负责：

- 蒸馏创作者经验
- 提出能力改进建议

这个 Skill 不负责：

- 直接修改其他 Skill
- 建立复杂知识管理系统
- 为每个创作者创建大量无实际价值文档

原则：

如果一个发现不能减少实际项目中的时间、错误或决策成本，不进入 Hermes。
