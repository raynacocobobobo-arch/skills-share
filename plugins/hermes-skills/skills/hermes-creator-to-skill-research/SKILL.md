# Hermes Creator To Skill Research

## Purpose

将优秀创作者的真实经验转化为 Hermes 可复用能力。

目标不是生成内容摘要，而是发现：

- 新工作流
- 新方法论
- 新判断标准
- 可以提升实际项目效率的能力

输入：

- YouTube 字幕
- 文章
- GitHub 项目
- 教程

输出：

- 创作者蒸馏分析
- 可复用原则
- Hermes 能力影响判断
- 必要时生成 Skill 修改建议

## Core Rule

不要：

- 生成普通视频摘要
- 罗列工具名称
- 因为一个案例就新增 Skill
- 设计复杂但无法使用的知识体系

重点回答：

1. 创作者解决了什么实际问题？
2. 他采用了什么工作流程？
3. 哪些经验可以迁移到其他项目？
4. Hermes 当前是否已经具备？
5. 如果缺失，最小应该如何补充？

## Workflow

原始素材

↓

完整阅读素材

↓

提取关键原文证据

↓

提取创作者工作流

↓

提炼可复用原则

↓

判断实际价值

↓

和已有 Hermes 能力比较

↓

生成最小修改建议

## Output Requirements

每次分析必须包含：

# Creator Distillation

## 来源

作者、素材、背景。

## 核心问题

这个创作者试图解决什么问题？

## 关键原文证据

格式：

原文片段：

解释：

提炼原则：

## 创作者工作流

拆解真实执行流程。

## 新发现的方法

只保留可迁移经验。

## 与已有 Hermes 能力比较

判断：

- 已覆盖
- 部分缺失
- 完全缺失

## Skill 影响

如果需要修改：

- 修改哪个文件
- 为什么修改
- 最小修改内容

## Practical Value

判断该经验是否值得进入 Hermes。

低价值内容：

- 单个工具新闻
- 临时模型效果
- 无法复用的技巧

高价值内容：

- 工作流程
- 判断方法
- 可持续复用原则

## Evidence Rule

所有重要结论必须能够追溯到原始素材。

禁止根据标题、摘要或二手描述生成结论。

## Boundary

这个 Skill 负责：

- 蒸馏创作者经验
- 提出能力改进建议

这个 Skill 不负责：

- 直接修改其他 Skill
- 建立复杂知识管理系统
- 为每个创作者创建大量无实际价值文档

原则：

如果一个发现不能减少实际项目中的时间、错误或决策成本，不进入 Hermes。
