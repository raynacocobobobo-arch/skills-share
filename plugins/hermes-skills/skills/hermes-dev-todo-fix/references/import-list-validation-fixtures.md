# 导入列表防丢验证夹具

## 触发场景

修改 HermesTodo 的“导入列表”解析、AI suggestions 清洗、章节标题过滤、最终写库过滤后，必须跑一组夹具验证：

1. 无效结构/解释句不会进入待办。
2. 有效任务不会被过滤误删。
3. 数量、条件、地点、时间、提醒、说明等细节保留到 `note`。
4. 章节标题里的真实分类名可提取为 `category`，但章节编号本身不进待办。

## 最小测试样例

```text
第五部分：药品准备
欧洲药店买药非常麻烦，尽量国内准备好。
布洛芬 2盒 | 退烧止痛，成人用
蒙脱石散 1盒 | 腹泻备用
第六部分：证件材料
为什么要准备这些？入境和酒店可能会查。
护照 | 有效期6个月以上
身份证 | 放钱包备用
Part 7 Payment
Visa信用卡 | 开通境外支付
现金欧元 | 小额零钱
```

## 关键坑

### 1. Swift 正则不要假插值

错误写法：

```swift
#"^第[0-9\#(cnNum)]+[章节部分篇类项点]..."#
```

这里 `cnNum` 不会被插值，实际正则只匹配字符 `c/n/N/u/m` 等字面量。应改为字符串拼接：

```swift
let cnNum = "零一二两三四五六七八九十百千万壹贰叁肆伍陆柒捌玖拾"
let numToken = "[0-9" + cnNum + "]+"
let unitToken = "(章节|章|节|部分|部|篇|类别|类|事项|项|点)"
let pattern = "^第" + numToken + unitToken + #"(\s*[:：、.．\-)）]?\s*.*)?$"#
```

### 2. “部分”不能写成字符类

`[章节部分篇类项点]` 会把 `部分` 拆成 `部` 或 `分` 单字，导致提取分类时可能残留 `分：药品准备`。应使用分组：

```swift
let unitToken = "(章节|章|节|部分|部|篇|类别|类|事项|项|点)"
```

### 3. 修误入时同步测防丢

用户明确要求“还要验证一下，没有丢东西”。以后只要收紧过滤规则，不只测 `第五部分/第六部分` 被删，还要同步测真实项目和备注没有被删。验证失败不能汇报完成。
