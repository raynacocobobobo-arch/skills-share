# 互动游戏设计 · Interactive Game Design

用于帮助用户设计和落地《机械迷城》类互动游戏：**点触式冒险 + 环境解谜 + 无对白叙事 + 手绘/机械世界观 + 交互节奏控制**。

## 核心判断

用户说“想做一个机械迷城类互动游戏”时，不要只给泛泛游戏设计建议。它的本质是：

1. **点触冒险**：玩家通过观察、点击、拖拽、组合推进。
2. **环境谜题**：谜题嵌在场景和机器系统里，不是独立脑筋急转弯。
3. **无对白叙事**：用动作、表情、机器反馈、场景痕迹讲故事。
4. **视觉引导**：每个画面既是美术场景，也是可交互地图。
5. **微型闭环**：每个场景必须给玩家“目标 → 尝试 → 反馈 → 小胜利”。

## 推荐资料框架

按任务用途分类，而不是堆书名：

1. **游戏设计核心**
   - Jesse Schell, *The Art of Game Design: A Book of Lenses*：体验优先、从玩家感受倒推机制。
   - Tracy Fullerton, *Game Design Workshop*：原型、playtest、迭代、游戏设计文档。

2. **谜题与关卡**
   - Scott Rogers, *Level Up!*：关卡节奏、道具、UI、反馈。
   - GDC / Jonathan Blow / The Witness 相关谜题设计演讲：系统化谜题、规则教学、组合难度。

3. **叙事与环境叙事**
   - Evan Skolnick, *Video Game Storytelling*：角色动机、互动叙事、非对白表达。
   - 电影美术、主题公园、场景设计资料：用空间痕迹讲故事。

4. **交互与可理解性**
   - Steve Krug, *Don’t Make Me Think*：玩家一眼知道能点哪里、点击后有反馈。
   - Alan Cooper, *About Face*：状态、心智模型、错误恢复。

5. **视觉叙事与构图**
   - Marcos Mateu-Mestre, *Framed Ink*：视线引导、光影、场景戏剧性。
   - *The Skillful Huntsman*：从关键词发展角色/场景/道具世界观。

## 默认工作流：先做 10 分钟 Demo

不要先劝用户读完一堆书。默认建议用户先做一个 **10分钟可玩的 Demo**，因为它能同时验证美术、交互、谜题、叙事和技术。

### Demo 模板

> 一个小机器人在废弃修理铺醒来，通过修好一台老式收音机，打开通往城市街道的门。

结构：

1. **场景**：废弃修理铺。
2. **目标**：开门出去。
3. **障碍**：门锁没电 / 机械卡死。
4. **线索**：墙上破损线路图、闪烁灯、断掉电线。
5. **道具**：铜线、旧灯泡、齿轮、旧电池。
6. **组合**：导电 / 传动 / 替换零件 / 修复机器。
7. **反馈**：灯亮、机器咔哒启动、收音机响、门打开、远处城市亮起。

## 谜题设计公式

每个谜题用这个表写清楚：

| 项 | 问题 |
|---|---|
| 目标 | 玩家现在想完成什么？ |
| 障碍 | 为什么现在做不到？ |
| 线索 | 玩家在哪里看出解决方向？ |
| 可交互物 | 哪些东西能点/拖/拿/组合？ |
| 规则 | 这个谜题教玩家什么新规则？ |
| 组合 | 玩家需要把哪些动作串起来？ |
| 反馈 | 成功/失败/半成功分别如何反馈？ |
| 叙事意义 | 这个谜题如何推进世界观或角色？ |

硬规则：

- 一个谜题只教一个新规则。
- 难度来自组合和理解，不来自像素级找东西。
- 谜题必须推进故事，不做纯装饰谜题。
- 玩家可以不知道答案，但必须知道“还能试什么”。
- 所有可点击物有视觉暗示，但不要像现代按钮一样突兀。

## 无对白叙事规则

优先使用：

- 角色表情、姿态、手势。
- 机器反应：冒烟、卡顿、闪灯、咔哒声。
- 场景痕迹：旧照片、涂鸦、破损标牌、遗留工具。
- 背景角色小动作。
- 小动画反馈，而不是文字解释。

避免：

- 大段旁白。
- UI 说明书。
- 物品说明写答案。
- 现实逻辑不成立的“魔法组合”。

## 美术世界观规则

先定统一世界观语言，避免“每个场景都好看但不像一个游戏”。

- **材质**：铁锈、铜、玻璃、旧纸、电线、油污。
- **形状**：齿轮、弯管、铆钉、圆形仪表、笨重机械。
- **色彩**：灰绿、锈红、暗黄、脏蓝、低饱和暖光。
- **运动**：咔哒、抖动、冒烟、弹簧回弹、齿轮迟滞。
- **交互语法**：修、拼、接、替换、导电、传动、开关、调频。

## 交付产物

根据用户阶段给对应产物：

1. **概念阶段**：世界观一页纸、核心体验、主角限制、参考图方向。
2. **Demo阶段**：10分钟流程图、场景清单、可点击物清单、谜题表。
3. **原型阶段**：HTML交互原型 / Godot / Unity 原型。
4. **美术阶段**：场景构图草图、材质板、色彩板、角色动作表。
5. **测试阶段**：卡点记录、玩家误解点、谜题重排建议。

## 与 Godot / huashu-design 的协作

如果用户要“我来直接搭工程 / 用 Godot 做游戏原型 / 不想手动点 GUI”：优先参考 `references/godot-click-adventure-scaffold.md`，生成 Godot 4.x 白盒项目，包含 Autoload `GameState`、通用 `Hotspot`、背包栏、场景切换和主线状态逻辑。Godot 更适合 Agent 直接写文件落地。

如果用户要“看得见、能点”的高保真网页原型：再加载 `huashu-design`，做 HTML 交互 Demo。此 skill 负责游戏设计结构；`huashu-design` 负责视觉和交互原型呈现。
