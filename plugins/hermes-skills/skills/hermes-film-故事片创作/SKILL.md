# 故事片创作 v13.2

## 0. 核心目标

本技能不是把故事强行塞进某一种编剧模板，而是把用户意图、已有版本、事实材料、人物关系和电影方法组织成一部：

- 逻辑成立；
- 人物可信；
- 能拍、能演；
- 观众能看懂；
- 在项目需要时能够明确完成价值表达的故事。

默认优先级：

> **来源正确 > 事实成立 > 故事因果 > 人物行动 > 人话表达 > 主题准确 > 形式技巧 > 文学漂亮。**

任何三幕式、15 节拍、英雄之旅、救猫咪、潜台词、象征、视觉母题，都只能服务于当前问题，不能反过来支配故事。

---

# 一、启动前先判断任务模式

不要把所有请求都当成“从零创作”。先判断本轮属于哪一种：

- **新写**：没有已认可基线，从需求、人物、故事发动机开始。
- **大改**：用户明确允许结构重构，可调整场次、关系、高潮和结尾。
- **局部改**：只修改指定场次、段落、对白、旁白或问题。
- **诊断**：先指出问题和根因，不默认改写全文。
- **格式化**：内容原则上不变，只处理标准剧本格式或交付形式。

如果用户已经给出完整稿、Word、上一版或说“在这个版本上改”，该版本就是基线。

## 1.1 最小改动原则

**用户要求“修改”时，默认不是“重写”。**

每次修订前内部划分：

| 保持不动 | 本轮必须修改 | 仅在必要时连带调整 |
|---|---|---|
| 已认可结构、人物、事实、台词、结尾 | 用户明确指出的问题 | 解决该问题不可避免的上下游 |

禁止：
- 修一句对白，顺手改变人物关系；
- 修一场节奏，擅自重做整个结尾；
- 用户只说“怪”，就全盘换结构；
- 用新创意覆盖已认可资产，却没有逐项对比。

涉及既有稿修订时，必须读取 `references/revision-control.md`。

用户出现“好很多了 / 大概意思对 / 我喜欢这个故事 / 就这个方向，只是……”等软确认时，当前版本自动成为新的工作基线；后续只重新打开用户点名的问题，默认执行 delta-only 局部修改，不得把窄修改重新扩成整版重写。

# 二、信息源优先级与状态

## 2.1 信息源优先级

发生冲突时，按以下顺序处理：

1. 用户当前最新明确要求；
2. 客户/项目所有者明确批准的要求、事实、表述；
3. 官方或专业核验过的事实与行业流程；
4. 用户已认可的上一版剧情、人物、结构和表达；
5. 当前项目锁定决策；
6. 合理的非专业叙事推断；
7. 通用编剧方法与模板。

低优先级内容不得覆盖高优先级内容。

## 2.2 统一事实状态

重要事实、口径和修改权限用以下状态管理：

- **LOCKED**：用户/客户已经确认或明确要求不再改；除非被重新打开，否则不得漂移。
- **CONFIRMED**：有权威证据支持，可以作为事实使用。
- **TENTATIVE**：目前可暂用但仍待确认，必须保留不确定性。
- **CONFLICT**：多个来源互相冲突；不得靠直觉静默选择。
- **INFERRED**：仅用于非专业、非安全性的叙事连接推断。
- **DO_NOT_INVENT**：技术步骤、安全动作、历史事实、隐私、医疗/法律/专业权限等禁止自行补写。

真实项目里，不能把 TENTATIVE 或 CONFLICT 写成 CONFIRMED。

# 三、项目模式识别

不同项目模式不能套同一套冲突与结尾规则。

## A. 原创虚构故事片

允许较高虚构自由度，以人物欲望、选择、阻力和代价为核心。

## B. 真实原型 / 行业委托微电影

事实和人物信誉优先。冲突可来自：

- 主角认知偏差；
- 工作目标与现实流程的冲突；
- 时间、距离、资源和权限；
- 两个都合理的目标发生竞争；
- 信息不完整或判断不能被草率推进；
- 镜头、传播或个人目标与真实工作优先级不同。

不要为了“有戏”强行制造坏人、冷遇、争吵、违规、险情或事故。

此模式必须读取 `references/commissioned-realism.md`。

## C. 纪录剧情混合片

明确区分：

- 剧情表演段；
- 真实纪录/采访段；
- 历史或资料影像。

从剧情转入纪录必须完成或重新定义前面的戏剧问题，不能只是片尾堆素材。

## D. 极短篇 / 视觉短片

当任务属于以下任一情况时，额外读取 `references/short-form-visual-story.md`：

- 约 1–5 分钟的剧情短片；
- 三分钟小说 / 极短篇；
- 单张或少量概念图发展出的短故事；
- 用户要求“少对白、少解释、更多用画面讲”；
- 以平行蒙太奇、仪式语言、广播/誓词与现实动作并置为主要叙事手段。

该模式是压缩换挡，不替代主 Skill 的因果、修订权限、人物选择和真实性规则。

## Reference Routing

当当前问题需要本 Skill 自带 references 之外的专业剧作、导演、短片或纪录方法支持时，不直接加载整本专业书：

1. 先读取 `manifests/reference-router.md`；
2. 再读取路由指向的对应 `.index.md`；
3. 只有索引明确指向且当前症状确实需要时，才读取原文对应章节。

典型触发：主题/人物/冲突/结构诊断反复无解、复杂短片压缩、视觉叙事、导演视点、场景调度、纪录剧情混合或需要理论依据的改编判断。普通局部改稿若现有 Skill 与自带 references 已足够，不额外加载专业书。

专业参考书只作为诊断与方法补充；不得覆盖用户最新要求、LOCKED/CONFIRMED 状态、已认可基线和事实优先级。

# 四、项目锁定表

长项目必须维护一张当前有效的锁定表；可在项目文件或当前上下文中维护。

至少包括：

| 项目 | 要回答的问题 |
|---|---|
| 类型/时长 | 这是哪一种故事、预计多长 |
| 主角 | 观众跟谁走 |
| 外部目标 | 主角具体要完成什么 |
| 初始误判/缺口 | 他一开始哪里看错或缺什么 |
| 核心阻力 | 什么持续阻碍目标 |
| 主主题 | 影片最终真正要说什么 |
| 次主题/机制 | 主主题为什么成立、如何延续 |
| 戏剧问题 | 观众一路想知道什么 |
| 高潮功能 | 高潮证明什么 |
| 最终选择 | 主角最后做了什么不同的选择 |
| 结尾定调 | 开放还是明确回答 |
| 必须保留 | 用户/客户指定资产 |
| 禁止事项 | 明确不能出现的内容 |
| 待核实 | 尚未 CONFIRMED 的事实 |

### 主题层级

至少区分：

1. 主主题；
2. 机制/次主题；
3. 叙事装置；
4. 视觉/动作母题。

机制不能因为写得顺就自动升级成主主题；装置也不能替代主题。

# 五、故事发动机：先有因果，再谈结构

写大纲前先回答：

> 主角因为某个欲望、误判或缺口，想完成一个具体目标；他采取行动，却被现实、人物或规则不断反证；他开始调整方法；高潮让前面已经建立的行为和关系得到验证；最后他在相似刺激下做出与开头不同的具体选择。

如果这条因果链说不清，不进入完整分场。

## 5.1 人物弧必须落到选择

不要只写“明白了、感动了、成长了”。

检查：
- 开头面对某类刺激，他怎么选？
- 结尾面对同类或镜像刺激，他怎么选？

**人物弧 = 同类情境中的不同选择。**

## 5.2 高潮不是凭空制造主题

高潮应兑现前文已存在的：
- 行为习惯；
- 人物关系；
- 决策方式；
- 代价；
- 信息或承诺。

如果删掉前文铺垫，高潮仍完全成立，说明前文可能只是素材堆积。

## 5.3 But / Therefore 因果检查

连续事件优先尝试用“**但是 / 所以**”连接，而不是“然后 / 接着”。

最小检查式：

> A，**但是** B → **所以** C → **但是** D → **所以** E。

如果核心梗概、相邻场次或关键动作主要只能写成“A，然后 B，然后 C”，优先判断为事件罗列。先补因果或删除无效节点，不要靠更多细节制造推进感。

## 5.4 硬伤先删后解释

当用户问“他为什么会这么做 / 为什么偏偏这样 / 这不合理”时，先检查动作或机制本身是否应当存在。

优先顺序：
1. 能否删除这个人为安排，让因果自然成立；
2. 能否改成更符合人物目标、岗位、时间和空间的动作；
3. 只有前两项都不行时，才补最短必要信息。

**不要用更多设定、对白、旁白去圆一个本来就不成立的动作。**

## 5.5 不可逆困境六问

凡高潮涉及“只能他做 / 最后一人 / 牺牲 / 二选一 / 不可逆选择”，正式写高潮前必须回答：

1. 为什么偏偏是这个人？
2. 为什么偏偏是现在？
3. 为什么别人不能解决？
4. 为什么不存在一个显而易见的第三方案？
5. 两个选择分别造成什么明确且不同的后果？
6. 这个困境是前面因果逼出来的，还是作者临时摆出来的？

任一关键问题答不出来，先修故事机制，不写牺牲戏和高潮台词。

## 5.6 Setup / Payoff 不只回收，还应争取意义变化

有效回收至少做到“前面建立，后面兑现”。更强的回收会让同一个：
- 句子；
- 动作；
- 物件；
- 场景；
- 规则；
- 视觉母题；

在结尾获得与开头不同、但由前文自然累积出的意义。

不要为了“有反转”硬改事实；优先追求**意义变化**而不是纯信息翻牌。

# 六、七阶段工作流

## 阶段 1：上下文与修改权限

必须：
1. 读完整当前稿、上一版、客户/用户意见和相关附件；
2. 判断新写 / 大改 / 局部改 / 诊断 / 格式化；
3. 提取 LOCKED、CONFIRMED、TENTATIVE、CONFLICT；
4. 写清本轮修改边界。

如果任务中途新增 Word、最终稿、客户反馈或用户宣布某部分“定稿/不要动”，立即更新修改权限并按 Router 重新检查 supporting skill。

如果上一轮已被用户软确认而本轮只补一个局部条件，优先只修改该条件及不可避免的直接后果，不重新发明已被接受的故事。

## 阶段 2：素材、事实与可拍性

真实题材建立事实账本和连续性信息：
- 相对时间；
- 人物在场/离场；
- 地点与移动；
- 工作/岗位状态；
- 道具/信息状态；
- 权限与拍摄边界；
- 非职业演员难度。

遇到专业事实不确定时，优先降维写成可观察状态，并标记 TENTATIVE 或 DO_NOT_INVENT。

## 阶段 3：故事诊断

用户反馈先诊断层级：

| 症状 | 先检查 |
|---|---|
| 没意思 | 目标、选择、代价、关键转折 |
| 流水账 | 场与场是否有因果、变量是否变化 |
| 太复杂 | 信息量、角色数、执行成本 |
| 偏题 | 主主题是否被支线或装置替换 |
| 不合理 | 时间、空间、事实、岗位、权限；先删/改硬伤动作，再考虑解释 |
| 不是人话/很怪 | 对白和旁白语域 |
| 太像宣传片 | 人物是否在替作者说结论 |
| 人物没变化 | 是否出现镜像情境和不同选择 |
| 水词/水动作多 | 每个动作、句子是否改变变量或承担必要叙事功能 |
| “不是我要改的地方” | 是否越过上一版软确认和 delta 边界 |

不要把“再加细节”当作所有问题的解法。

## 阶段 4：因果大纲与场景链

每场至少回答：
1. 开场状态是什么？
2. 人物这场想做什么？
3. 现实发生什么？
4. 人物作出什么选择/调整？
5. 场末什么变量发生了变化？
6. 这个结果如何触发下一场或改变后续？

如果第 5、6 项都答不出，优先考虑删除、合并或改成蒙太奇。

连续多场如果只是“看到新细节”，没有选择、阻力、关系或信息变化，通常属于观察清单，不是戏剧推进。

完成场景链后，快速做一次 But / Therefore 复述。相邻关键节点如果只能用“然后”连接，返回修因果。

## 阶段 5：正式剧本

正式剧本遵守 `中文剧本格式` supporting skill：
- 当前时态；
- 动作只写可见可听；
- 场标统一；
- 角色名称统一；
- V.O./O.S. 使用准确。

心理变化的外化优先级：
1. 选择变化；
2. 注意力变化；
3. 职业/工具行为变化；
4. 身体动作；
5. 关系行动；
6. 对白；
7. 旁白。

不是所有心理都必须隐藏。如果只靠动作会造成实质误解，可用最短旁白澄清一次。

### 动作删水器

“可见可听”不等于“值得写”。每个明显动作至少应承担一项：
- 改变局面；
- 暴露/改变关系；
- 提供后面必须使用的信息；
- 制造或释放悬念；
- 建立或兑现 setup/payoff；
- 完成人物选择；
- 用画面替代本来需要解释的文字。

如果都不承担，优先删除或合并。尤其警惕连续的“看一眼 / 低头 / 停顿 / 叹气 / 走几步 / 又看一眼”只负责制造电影感，却没有改变任何变量。

## 阶段 6：对白与旁白终校

涉及对白/旁白写作或用户反馈“不是人话、怪、解释太多”时，必须读取 `references/dialogue-vo-naturalness.md`。

### 人话五检

逐句过：
- 口腔测试；
- 场景测试；
- 身份测试；
- 抽象词测试；
- 作者测试。

### 旁白只承担

核心只允许承担：
1. 框定；
2. 心理澄清；
3. 时间压缩；
4. 项目需要时的最终定调。

旁白不能把**画面**刚演完的内容再**复读**一遍，也不能成为每个转折的解释器。

## 阶段 7：交付与回归

交付前重新对照：
- 用户最新要求；
- LOCKED 项；
- 用户软确认后的工作基线；
- 客户/事实来源；
- 修改边界；
- 连续性；
- 引用完整性；
- 正式剧本格式；
- 交付物是否真的属于本轮要求。

如果用户要求已有 Word 上修改，应保持领域 Skill 负责“改什么”，doc-reviewer 负责“怎样落回原文件副本”。不要因为出现 Word 就重新生成一个内容相似的新文档。

# 七、对白与旁白原则

更详细规则见 `references/dialogue-vo-naturalness.md`。

## 7.1 对白功能顺序

人物开口优先为了：
1. 处理眼前的事；
2. 影响对方；
3. 维持或改变关系；
4. 传递必要信息；
5. 暴露自己。

直接表达主题通常排最后。

正式术语不等于套话。判断它是否准确、是否属于这个人物、是否在当前场合承担真实专业含义，而不是建立“正式词一律删”的禁词表。

## 7.2 记忆句与伪金句

真正有效的记忆句来自处境、人物身份和动作积累；伪金句通常可以无损贴到很多别的项目里，只是在替作者总结。

不要按“金句数量”评价故事质量。

# 八、真实性、权限和非职业演员

真实原型、行业委托、专业题材必须遵守 `references/commissioned-realism.md`。

### 8.1 权限与知识边界

逐场检查：
- 谁能做这个动作？
- 谁只能观察？
- 这个人此刻是否能离开岗位？
- 角色是否可能知道这条信息？
- 拍摄人员/设备能否进入该区域？
- 这个动作是否能为了拍摄安全复演？

不允许用旁白去圆一个本来就不成立的专业动作。

### 8.2 非职业演员

真实委托片默认考虑非职业演员可执行性。

优先：
- 熟悉动作；
- 短的场景语言；
- 简单走位；
- 真实关系行为；
- 通过选择和停顿完成情绪。

谨慎：
- 长独白；
- 哭戏；
- 精确爆发；
- 多人抢话；
- 危险动作复演。

能让真实行为完成的，不要求演员“演主题”。

# 九、连续性与引用完整性

## 9.1 故事连续性

完成分场后检查：
- 时间；
- 地点；
- 人物在场状态；
- 关键道具；
- 信息流；
- 服装/身体状态；
- 专业权限；
- 前一场造成的结果是否延续。

## 9.2 文档引用完整性

结构修改后必须做引用完整性检查。

凡发生**重命名、重编号、合并、拆分、移动、删除**，都必须搜索所有依赖引用，包括：
- 后文场号和章节号；
- 人物名称和别名；
- 制作说明、附录、核验说明；
- 表格、场景链、连续性表；
- 分镜、拍摄表、汇报稿等下游材料。

正文改对了，但制作说明仍引用旧场号，也属于修订失败。

# 十、结构理论与参考作品是可选工具

三幕式、**15 节拍**、**英雄之旅**、救猫咪、悲剧理论、潜台词系统、视觉母题等都属于**可选工具**。

- 可用于诊断当前已存在的问题；
- **不强制套**固定模板；
- 不得为了命中节拍制造不真实事件；
- 不得为了理论完整破坏用户已认可结构；
- 如果一个工具没有解决当前症状，就不加载它。

使用前问：

> 这个工具是在解决一个已观察到的问题，还是只是让方案看起来更专业？

后者不用。

## 10.1 参考作品只抽元模型，不做角色换皮

使用电影、小说、童话或经典母题作参考时，优先抽取：
- 欲望与阻力；
- 关系结构；
- 信息差；
- 信任/误判机制；
- 选择与代价；
- 因果顺序；
- 意义如何在结尾发生变化。

不要首先映射“谁等于原作哪个角色、哪个道具等于原作哪个道具、哪个桥段照搬哪个桥段”。

自检：如果能轻易写出“A 就是原作 X，B 就是原作 Y，这一场就是原作 Z”，说明抽象层级可能仍停留在换皮。继续向上抽象功能，再重新创造人物、环境和因果。

# 十一、结尾系统

## A. 作者型 / 开放型故事

允许观众完成最后一步判断。

## B. 企业、品牌、机构委托剧情片

如果任务明确要求价值结论，影片可以替观众完成最后定调，但必须建立在前面证据充分之后。

推荐顺序：

> 动作证明 → 人物选择 → 余波/结果 → 最短必要定义 → 已批准结尾表达。

不要先喊结论，再用场景装饰它。

### 11.1 结尾优先改变前文的意义

结尾除了回答“发生了什么”，还应检查是否能让前文一个已建立的动作、句子、物件或规则获得新的理解。优先用前文已有资产完成余味，不要在最后临时增加一个新设定来制造惊讶。

# 十二、交付规范

## 12.1 分析阶段

优先输出：
- 结论；
- 硬伤；
- 根因；
- 修改方向；
- 保留项/LOCKED 项。

不要先讲理论史。

## 12.2 大纲阶段

输出因果场景链，不只列“发生了什么”。

## 12.3 正式剧本

遵守中文剧本格式。动作可拍、对白可演、专业边界可核验。

## 12.4 修订稿

重要改版可附简短 change log：
- 改了什么；
- 为什么；
- 哪些核心未动。

已有文档任务不要把原文件当素材仓。

# 十三、终稿质量门

只有以下硬伤都清零后才能称为终稿。

### A. 来源与修订
- [ ] 已读完整基准稿和最新意见
- [ ] 没有越过 LOCKED 内容
- [ ] 软确认后的 baseline 没有被窄修改意外重写
- [ ] 没有把 TENTATIVE/CONFLICT 写成 CONFIRMED
- [ ] 局部改没有扩散成无授权重写

### B. 故事
- [ ] 主角目标清楚
- [ ] 阻力持续作用
- [ ] 场与场存在因果，关键节点能用 But / Therefore 复述
- [ ] 硬伤没有靠解释强行圆过去
- [ ] 不可逆困境通过六问，没有明显第三条路
- [ ] 高潮兑现前面铺垫
- [ ] 最终变化通过具体选择可见
- [ ] setup/payoff 至少完成回收；关键母题若可行，产生意义变化

### C. 主题
- [ ] 主主题、机制、装置没有混层
- [ ] 支线没有抢走主主题
- [ ] 结尾定调符合项目模式

### D. 人物与语言
- [ ] 对白通过人话五检
- [ ] 人物没有替作者总结
- [ ] 旁白必要、直接、不复读画面
- [ ] 动作通过删水器，不靠无效停顿制造电影感
- [ ] 正式术语按语境判断，不被机械删除

### E. 真实性与执行
- [ ] 时间/空间/信息流成立
- [ ] 专业事实和权限不臆造
- [ ] DO_NOT_INVENT 内容没有被补写
- [ ] 非职业演员能够完成
- [ ] 不要求危险动作为了拍摄复演

### F. 修订完整性
- [ ] 重命名/重编号/合并/删除后已检查所有引用
- [ ] 附录、制作说明和下游表格没有指向旧版本实体
- [ ] Existing Word 修改仍基于原文件副本

### G. 交付
- [ ] 用户要完整稿时交付完整稿
- [ ] 用户只要局部修改时没有擅自扩大范围
- [ ] 输出格式与当前 Router / supporting skill 一致

只有全部不存在硬伤，才标记为终稿。
